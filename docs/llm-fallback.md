# AI text-model fallback

The ordered chain is opt-in through the server-only `LLM_MODELS` environment variable. Supply one to five entries as `provider:model`, separated by commas, such as `anthropic:<verified-model-id>,openai:<verified-model-id>,gemini:<verified-model-id>,groq:<verified-model-id>`. Configure the matching `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` and/or `GROQ_API_KEY` in the secret store. Optionally set `LLM_RATE_LIMITS` to comma-separated `provider:model=requests_per_minute` entries for configured models. Groq can host supported open models including Qwen; only models supporting strict structured output are suitable. Model IDs and premium-to-budget order are selected by the operator, not defaults in this document. Free allowances are not guaranteed and must be checked against provider terms. Keep provider access, data-processing terms, model quality and spending limits under review.

The text chain serves Studio draft extraction, refinement, proposed fixes and the student tutor via `defaultRecallModel`. It tries the next configured model after a rate/quota limit, provider 5xx, or connection/timeout failure. Anthropic's explicit insufficient-credit error is also eligible. Anthropic provider-side fallback is disabled so it cannot bypass the configured order or route around a refusal. Configuration, authentication, malformed schema, refusal, incomplete response and invalid JSON fail closed and do not trigger a different model. If all candidates are unavailable the operation fails with a generic retry message. Source inputs and keys are not written to fallback logs. Successful output retains the serving provider/model; OpenAI costs and non-default Claude pricing are recorded as unknown, not zero. Requests can still be charged by a provider before a timeout; cap budgets and assess latency. A database-backed cooldown skips recently unavailable models for 30 seconds by default, or a bounded Retry-After value when supplied. Optional request limits are shared, fixed one-minute windows per configured model; unlisted models are unrestricted, boundary bursts are possible, and this does not enforce provider-wide or token-based quotas, concurrency or spending caps. If cooldown storage is unavailable the chain continues without it; if an enabled rate-limit store fails the request fails closed.

OpenAI uses the Responses API with JSON Schema and `store:false`; provider terms and appropriate data protection agreements must be approved before enabling it. The existing untrusted-input and human-review controls still apply, but model switching needs evaluation against the medical gold set before clinical use. The server strips some common identifiers from text, not all possible personal information.

OCR is separate from the text chain. The local implementation uses Tesseract for images and scanned PDF pages without sending the originals to a provider. Mixed documents use selectable text where present and OCR for pages without it; image-only content on a page with substantial selectable text may be missed. Deployed-runtime behavior remains unverified. Text validation still occurs in each calling service; invalid content does not publish automatically. No automatic failover for invalid or refused model output is provided, to avoid bypassing safeguards.

The configured chain allocates a shared network time budget across remaining models (up to 240 seconds for Studio and 50 seconds for the tutor), with each adapter aborting its own request on timeout. Database and application work also consumes execution time, so these budgets do not guarantee completion before the hosting limit. Equal division can be too short for slower models, particularly for five-model tutor chains; evaluate real workloads and hosting limits before launch. Unconfigured local CLI behavior is unchanged.

If `LLM_MODELS` is unset, existing Claude API/local-development behavior is preserved. Do not configure an empty or partially keyed chain. Never put keys in the repository or chat. This change is local until reviewed and deployed; it does not alter the already deployed Vercel project.
